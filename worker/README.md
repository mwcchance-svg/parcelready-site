# Store worker: deploy notes

The worker is the ParcelReady store brain (see ../STORE-ARCHITECTURE.md).
It deploys after the Matt sitting creates the ParcelReady Stripe account.
Nothing here runs before then; the static site deploys independently.

Deploy sequence (HQ and Mason, no Matt hands beyond the sitting):

1. Cloudflare: create R2 bucket `parcelready-files` and two KV namespaces
   (tokens, leads); put their ids in wrangler.toml.
2. Upload pack files to R2 under the exact keys in store-registry.json
   (file_key for full packs, sample_file_key for samples). The registry is
   regenerated by ../build.py; never hand edit it.
3. `wrangler secret put` for STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET,
   RESEND_API_KEY, DELIVERY_SECRET.
4. `wrangler deploy`, then attach the route parcelreadydata.com/api/* so
   the static site's relative /api calls reach the worker.
5. In Stripe: create the webhook endpoint for the worker URL with events
   checkout.session.completed and invoice.paid; put its signing secret in
   as STRIPE_WEBHOOK_SECRET and redeploy.
6. Run ../scripts/stripe_sync.py (live mode) to create products and
   prices for every stripe mode pack; commit the returned ids.
7. Place a live test purchase on the cheapest stripe pack, confirm the
   delivery email and download, then refund it in Stripe.

Leads: Herald reads sample leads from the LEADS KV namespace (export with
`wrangler kv key list` / `get`) and from the notification copy that lands
in hello@parcelreadydata.com on every capture.
