# ParcelReady website: deploy runbook

Site: parcelreadydata.com (domain already owned; email already runs on it).
Pattern: GitHub Pages, the same $0 pattern as the Tool One storefront
(getinstantquotetool.com under mwcchance-svg). No new accounts, no spend.

## What is in this folder

- index.html, catalog.html, sample.html, verify.html: the hand built pages.
- packs/*.html: one page per pack, GENERATED by build.py from catalog.json.
  Never edit a pack page by hand. Edit catalog.json and rerun: python3 build.py
- states/: GENERATED state-first architecture (Matt's spec, Nov 22, 2026).
  states/index.html lists all 50 states with live counts; each state hub
  (states/<state>/) shows every pack held for that state plus its category
  index; each state x category page (states/<state>/<category>/, 600 pages
  across the 12-category taxonomy) is a deep link target for outreach, e.g.
  parcelreadydata.com/states/illinois/plumbing/ lands an Illinois plumbing
  prospect on their exact page, with a sample request CTA that opens the
  sample form with that state and category preselected. Empty combinations
  say so honestly (in production, or not built yet) instead of faking stock.
- sitemap.xml (666 URLs) and robots.txt: GENERATED, for organic discovery.
- Freshness: every pack carries data_as_of in catalog.json. It renders on
  the pack page, its catalog card, its state hub, and its category page.
  When Relay's refresh system rolls a pack's data, update that pack's
  data_as_of (and sample_csv if the sample file changed) and rerun build.py;
  every surface updates in one commit. No redesign, ever.
- catalog.json: the catalog source of truth. A new Relay pack is added as one
  new entry (title, trade, metro, verified row count, price, Gumroad links,
  cover image, inside list, honest limits), then build.py regenerates the pack
  page, the catalog cards, the browse filters, and the build sequence matrix.
  No redesign, ever. Prices, counts, and links are copied from the governing
  store records, never reconstructed from memory.
- assets/: site.css, site.js, catalog-data.js (generated), covers (the real
  data preview covers from the Nov 22 store fix), the ParcelReady logo, and
  data/ (generated sample JSON powering the live sample explorer on the home
  page and the trade pack pages; regenerated by build.py from the packs'
  sample CSVs in ~/workspace/data-products/lead-packs).
- CNAME: parcelreadydata.com (already in place for GitHub Pages).

## Deploy steps (one sitting, in order)

1. Create the repo under mwcchance-svg (suggested name: parcelready-site),
   public, and push this folder's contents as ONE commit (standing rule:
   one commit per deploy, complete file set).
2. In the repo: Settings, Pages, deploy from branch main, root folder.
   Custom domain: parcelreadydata.com (the CNAME file carries it).
   Enforce HTTPS once the certificate issues.
3. DNS, at the domain's CURRENT DNS host only. Do not move DNS service and
   do not touch MX, TXT (SPF), or DKIM records: email on this domain is live
   and verified. Add only:
   - Apex A records: 185.199.108.153, 185.199.109.153, 185.199.110.153,
     185.199.111.153
   - www CNAME: mwcchance-svg.github.io
   If the DNS host supports ALIAS/ANAME at the apex, that may replace the
   four A records. DNS host VERIFIED Nov 23, 2026 (HQ, public DNS lookup):
   Squarespace DNS, nameservers nsa1 through nsa4.squarespacedns.com. The
   apex currently carries Squarespace's four A records (198.185.159.144,
   198.185.159.145, 198.49.23.144, 198.49.23.145) and www currently CNAMEs
   to ext-sq.squarespace.com; the deploy replaces exactly those with the
   records above. MX (1 smtp.google.com) and SPF (Google) verified present
   the same day and stay untouched.
4. Verify: https://parcelreadydata.com loads, a pack page loads, one Gumroad
   buy link and one free sample link click through, the sample form renders.

## Sample form activation (one click, Herald)

The sample request form posts through FormSubmit to
hello@parcelreadydata.com (no account, no cost). The FIRST real submission
triggers a one time activation email to that inbox; Herald clicks the
activation link once and every later submission arrives as a formatted
email with business name, trade, metro, and reply route. Until activation,
the form still submits but deliveries wait on that click. The three live
free samples are also linked directly on the sample page, so visitors are
never blocked by the form.

## After launch

- Herald's outreach can cite parcelreadydata.com as the catalog home.
- Relay adds each new pack to catalog.json at listing time (same sitting as
  the Gumroad publish and affiliate enablement), reruns build.py, one commit.

## Store layer (Matt's revised architecture, Nov 22, 2026)

- STORE-ARCHITECTURE.md is the governing design: Stripe checkout created
  programmatically from catalog.json, automated delivery, memberships on
  Stripe Billing, samples by email capture, Gumroad as feeder shelf only.
- worker/ holds the Cloudflare Worker (checkout, webhook, delivery, sample
  capture) and its deploy notes. It deploys after the Stripe sitting.
- scripts/stripe_sync.py creates Stripe products and prices from the
  registry (dry run works with no key). build.py emits
  worker/store-registry.json on every run; never hand edit it.
- Nothing in the store layer is live until the deploy sitting and the
  Stripe sitting have both happened. The site's forms and buttons carry
  honest launch fallbacks until the worker answers.
